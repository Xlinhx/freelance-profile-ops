# Framework Map Case Ngoài Dự Tính

Tài liệu này để agent xử lý các sản phẩm chưa từng quay trước đó mà không bị lệch tư duy.

## 1. Không đoán theo ví dụ cũ

Không được nghĩ kiểu:

- `trông giống SaaS`
- `trông giống education`
- `trông giống ecommerce`

Rồi copy grammar cũ.

Phải map theo các trục dưới đây.

## 2. Sáu trục bắt buộc

### A. Domain

Ví dụ:

- education
- ecommerce
- FnB
- SaaS / admin / CRM
- operations
- system scale
- internal tool
- community platform
- creative tool

### B. Buyer lens

Người mua thật đang quan tâm điều gì nhất:

- tăng doanh thu
- bớt việc tay
- kiểm soát vận hành
- tăng tốc xử lý
- giữ ổn định khi tải lớn
- tạo trải nghiệm mới
- theo dõi và audit

### C. Hero proof

Thứ phải đọng lại sau khi xem video:

- workflow
- role handoff
- throughput
- creativity
- logs / analytics
- volume / scale
- speed
- control

### D. Scene risk

Rủi ro chính khi quay:

- crop mất context
- proof quá nhỏ
- flow khó hiểu
- nhiều role dễ lẫn
- data nhạy cảm
- module quá nhiều
- text quá dày

### E. Interaction type

Sản phẩm này cần interaction kiểu nào:

- click / hover / type
- drag / drop
- branching / graph
- timeline / lifecycle
- dashboard proof
- modal / side panel
- feed / list / queue

### F. Visual pressure

Canvas có bị nặng không:

- thấp: có thể editorial hơn
- vừa: cần 1 proof chính + 1 proof phụ
- cao: phải split scene, không nhét

## 3. Từ mapping sang hướng quay

### Nếu buyer lens là control / vận hành

Ưu tiên:

- proof rõ
- state change rõ
- role handoff rõ
- timeline rail
- proof cascade

### Nếu buyer lens là novelty / creativity

Ưu tiên:

- hero feature khác biệt
- branch reveal
- reply lift
- expand-to-detail

### Nếu buyer lens là scale / throughput

Ưu tiên:

- system map
- shrink-to-system
- metrics
- logs
- queue / role / monitoring

## 4. Decision tree ngắn

### Câu 1

Người mua cần tin điều gì trước:

- `nó chạy được thật`
- `nó mới và khác`
- `nó scale được`
- `nó giảm đau vận hành`

### Câu 2

Viewer cần hiểu gì đầu tiên:

- đây là web gì
- ai dùng nó
- một thao tác đi đến kết quả nào
- vì sao nó hơn các tool thường

### Câu 3

Scene khó nhất của sản phẩm thuộc loại nào:

- breadth quá nhiều module
- detail cần đọc kỹ
- handoff giữa nhiều role
- graph / timeline / branching

Câu trả lời cho 3 câu này quyết định phần còn lại của storyboard.

## 5. Rule chống reuse sai

Nếu project mới dùng lại grammar của project cũ, phải chỉ ra được:

- buyer lens giống ở đâu
- proof style giống ở đâu
- interaction type giống ở đâu

Nếu không chỉ ra được, xem như đang reskin lười.
